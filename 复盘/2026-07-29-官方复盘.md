### 2. 修复两个真实 Bug

**Bug 1：`NEXT_PUBLIC_PAYPAL_CLIENT_ID` 前端拿不到**
- 现象：后端 create-order 正常（200），但前端弹窗报 "PayPal is not configured"
- 根因：`NEXT_PUBLIC_` 前缀的变量是**构建时**注入的，Vercel 上只加了服务端 3 个变量，漏了 `NEXT_PUBLIC_PAYPAL_CLIENT_ID` → 打包后的客户端 JS 里没有这个值
- 修复：在 Vercel Dashboard 补加 `NEXT_PUBLIC_PAYPAL_CLIENT_ID` 并 **Redeploy**

**Bug 2：PayPal 按钮金额错（$0.01 而非 $2.99）**
- 现象：弹窗显示 $0.01，付款后图片虽能下载，但金额不对
- 根因：`PaymentModal` 里把订单创建写在了 `onClick` 回调。PayPal SDK **不把 `onClick` 的返回值当订单 ID 用**，结果付的是按钮自动生成的默认订单（$0.01），我们 API 创建的 $2.99 订单被忽略
- 修复：改用 `createOrder` 回调返回我们的订单 ID

## 二、今日学习内容

### Next.js 环境变量：`NEXT_PUBLIC_` vs 普通变量

| 类型 | 注入时机 | 前端可见 | 改了要不要 redeploy |
|------|---------|---------|-------------------|
| `NEXT_PUBLIC_XXX` | **构建时**打包进客户端 JS | ✅ 是 | **必须 redeploy** |
| `XXX`（无前缀） | 运行时服务端读取 | ❌ 否 | 重新部署即可（无需改代码） |

**教训**：前端要用的变量（如 PayPal Client ID）必须是 `NEXT_PUBLIC_` 前缀，且**在 Vercel 构建之前就设好**，否则要 Redeploy 才生效。

### PayPal JS SDK 按钮回调

- `createOrder`：创建订单并返回订单 ID（**必须用它**，不是 onClick）
- `onClick`：返回 `true/false` 控制"是否继续打开 PayPal 弹窗"，返回值**不**当订单 ID
- `onApprove`：用户付款完成后触发，拿 `data.orderID` 调 capture
- `onError`：支付过程出错

## 五、教训

- `NEXT_PUBLIC_` 变量改了必须 Redeploy，不是改完就生效。
- PayPal SDK 的 `onClick` 不能用来创建订单 —— 必须用 `createOrder`。
